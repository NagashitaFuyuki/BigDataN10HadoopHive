Hướng dẫn cài đặt Hadoop và Hive trên Docker

Ubuntu 22.04Java 8Hadoop 3.3.6Hive 4.0.1Engine MapReduce / YARNMetastore Derby

Làm lần lượt từ Phần 1 đến Phần 10. Bấm Copy rồi dán vào terminal; khung xanh lá là kết quả cần thấy trước khi tick «Đã xong». Tiến độ được lưu trong trình duyệt.

1Chuẩn bị Docker

Tạo một container Ubuntu duy nhất (hadoop-master) chạy chế độ pseudo-distributed: NameNode, DataNode, ResourceManager, NodeManager và HiveServer2 cùng nằm trong container này.

1a

Cấp đủ RAM cho Docker

Job MapReduce cần tối thiểu ~3 GB cho YARN + ~1 GB cho HiveServer2 + các daemon HDFS. Docker nên có từ 6 GB RAM trở lên. Docker Desktop: Settings → Resources → Memory. Nếu dùng WSL2, tạo/sửa file %UserProfile%\.wslconfig:

File .wslconfig
[wsl2]
memory=8GB
processors=4
PowerShell / Terminal Windows
wsl --shutdown

Sau đó mở lại Docker Desktop.

Ghi chúMáy chỉ có 4–6 GB RAM: giảm yarn.nodemanager.resource.memory-mb xuống 2048 ở Phần 4 (giữ nguyên các giá trị còn lại).
1b

Tải image Ubuntu

Chạy lại được
PowerShell / Terminal Windows
docker pull ubuntu:22.04
1c

Tạo container hadoop-master (có mở đủ cổng)

Chạy 1 lần
PowerShell (dấu ` là xuống dòng; trên CMD/Linux dùng ^ hoặc \)
docker run -it -d --name hadoop-master -h hadoop-master `
  -p 10000:10000 -p 10002:10002 -p 9870:9870 -p 8088:8088 -p 19888:19888 `
  ubuntu:22.04

Ý nghĩa cổng: 10000 HiveServer2 (JDBC/IntelliJ) · 10002 giao diện HiveServer2 · 9870 giao diện HDFS · 8088 giao diện YARN · 19888 JobHistory.

Lưu ýContainer đã tồn tại (báo name is already in use)? Đừng tạo lại — chạy docker start hadoop-master. Nếu container đã tạo trước đó thiếu -p 10000:10000 thì xem mục Troubleshooting «IntelliJ không kết nối được».

Hướng dẫn này chỉ dùng 1 container (hadoop-master) chạy cả Hadoop lẫn Hive, không cần thêm node phụ.

3Biến môi trường và SSH

Đây là phần dễ hỏng ngầm nhất: file ~/.bashrc mặc định của Ubuntu thoát ngay ở dòng đầu với shell không tương tác, nên source ~/.bashrc trong script (hoặc khi Hadoop SSH vào chính nó) không nạp được HADOOP_HOME, JAVA_HOME, PATH. Vì vậy ta tách biến ra file riêng và chèn vào dòng đầu của .bashrc.

3a

Tạo file biến môi trường dùng chung

Chạy lại được
Trong container
cat > /root/hadoop-hive-env.sh <<'EOF'
# ===== Biến môi trường dùng chung cho Hadoop + Hive =====
export JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64
export HADOOP_HOME=/root/hadoop-3.3.6
export HADOOP_MAPRED_HOME=$HADOOP_HOME
export HADOOP_COMMON_HOME=$HADOOP_HOME
export HADOOP_HDFS_HOME=$HADOOP_HOME
export HADOOP_YARN_HOME=$HADOOP_HOME
export HADOOP_CONF_DIR=$HADOOP_HOME/etc/hadoop
export HIVE_HOME=/root/apache-hive-4.0.1-bin
export HIVE_CONF_DIR=$HIVE_HOME/conf
export PATH=$HADOOP_HOME/bin:$HADOOP_HOME/sbin:$HIVE_HOME/bin:$PATH
EOF
3b

Chạy lại được
Trong container
grep -q 'hadoop-hive-env.sh' /root/.bashrc || sed -i '1i source /root/hadoop-hive-env.sh' /root/.bashrc
source /root/hadoop-hive-env.sh
head -n 2 /root/.bashrc
Kết quả mong đợi
source /root/hadoop-hive-env.sh
Ghi chúNếu .bashrc của bạn đã có sẵn dòng export HADOOP_HOME... ở cuối thì cứ giữ, không xung đột.
3c

Cấu hình SSH không mật khẩu

Chạy lại được
Trong container
service ssh start
mkdir -p ~/.ssh && chmod 700 ~/.ssh
[ -f ~/.ssh/id_rsa ] || ssh-keygen -t rsa -P "" -f ~/.ssh/id_rsa
grep -qf ~/.ssh/id_rsa.pub ~/.ssh/authorized_keys 2>/dev/null || cat ~/.ssh/id_rsa.pub >> ~/.ssh/authorized_keys
chmod 600 ~/.ssh/authorized_keys
cat > ~/.ssh/config <<'EOF'
Host *
  StrictHostKeyChecking no
  UserKnownHostsFile /dev/null
  LogLevel ERROR
EOF
chmod 600 ~/.ssh/config

Hai dòng StrictHostKeyChecking no ngăn start-dfs.sh dừng lại hỏi «Are you sure you want to continue connecting?».

4Cấu hình Hadoop (đầy đủ)

Mỗi file được ghi đè hoàn toàn bằng cat > ... <<'EOF' nên chạy lại bao nhiêu lần cũng không bị lặp thẻ. Phần quan trọng nhất để MapReduce khởi chạy được là classpath (4.4, 4.5) và bộ nhớ/đĩa YARN (4.5, 4.6).

4a

hadoop-env.sh — JAVA_HOME và user chạy daemon

Chạy lại được
Trong container
F=/root/hadoop-3.3.6/etc/hadoop/hadoop-env.sh
grep -q 'GUIDE-HADOOP-ENV' $F || cat >> $F <<'EOF'

# ===== GUIDE-HADOOP-ENV =====
export JAVA_HOME=/usr/lib/jvm/java-8-openjdk-amd64
export HDFS_NAMENODE_USER=root
export HDFS_DATANODE_USER=root
export HDFS_SECONDARYNAMENODE_USER=root
export YARN_RESOURCEMANAGER_USER=root
export YARN_NODEMANAGER_USER=root
EOF
mkdir -p /root/hadoop-3.3.6/data/namenode /root/hadoop-3.3.6/data/datanode /root/hadoop-3.3.6/data/tmp
tail -n 10 $F

Khối lệnh có dấu hiệu GUIDE-HADOOP-ENV nên không bị append lặp.

hdfs-site.xml

Chạy lại được
Trong container
cat > /root/hadoop-3.3.6/etc/hadoop/hdfs-site.xml <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <property>
    <name>dfs.replication</name>

  <property>
    <name>dfs.namenode.name.dir</name>

  </property>
  <property>
    <name>dfs.datanode.data.dir</name>

Trong container

<configuration>

    <value>HADOOP_MAPRED_HOME=/root/hadoop-3.3.6</value>
  </property>
  <property>
    <name>yarn.app.mapreduce.am.resource.mb</name>
    <value>1024</value>
  </property>
  <property>
    <name>yarn.app.mapreduce.am.command-opts</name>
    <value>-Xmx768m</value>
  </property>
  <property>
    <name>mapreduce.map.memory.mb</name>
    <value>1024</value>
  </property>
  <property>
    <name>mapreduce.map.java.opts</name>
    <value>-Xmx768m</value>
  </property>
  <property>
    <name>mapreduce.reduce.memory.mb</name>
    <value>1024</value>
  </property>
  <property>

Lưu ýChỉ đặt HADOOP_MAPRED_HOME mà thiếu mapreduce.application.classpath là chưa đủ. Cặp -Xmx768m luôn phải nhỏ hơn memory.mb (1024).
4e

yarn-site.xml — classpath, bộ nhớ, kiểm tra đĩa

Chạy lại đượcQuan trọng
Trong container
cat > /root/hadoop-3.3.6/etc/hadoop/yarn-site.xml <<'EOF'
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <property>
    <name>yarn.resourcemanager.hostname</name>
    <value>hadoop-master</value>
  </property>
  <property>
    <name>yarn.nodemanager.aux-services</name>
    <value>mapreduce_shuffle</value>
  </property>
  <property>
    <name>yarn.nodemanager.env-whitelist</name>
    <value>JAVA_HOME,HADOOP_COMMON_HOME,HADOOP_HDFS_HOME,HADOOP_CONF_DIR,CLASSPATH_PREPEND_DISTCACHE,HADOOP_YARN_HOME,HADOOP_HOME,HADOOP_MAPRED_HOME,PATH,LANG,TZ</value>
  </property>
  <property>
    <name>yarn.application.classpath</name>
    <value>/root/hadoop-3.3.6/etc/hadoop,/root/hadoop-3.3.6/share/hadoop/common/*,/root/hadoop-3.3.6/share/hadoop/common/lib/*,/root/hadoop-3.3.6/share/hadoop/hdfs/*,/root/hadoop-3.3.6/share/hadoop/hdfs/lib/*,/root/hadoop-3.3.6/share/hadoop/mapreduce/*,/root/hadoop-3.3.6/share/hadoop/mapreduce/lib/*,/root/hadoop-3.3.6/share/hadoop/yarn/*,/root/hadoop-3.3.6/share/hadoop/yarn/lib/*</value>
  </property>
  <property>
    <name>yarn.nodemanager.resource.memory-mb</name>
    <value>3072</value>
  </property>
  <property>
    <name>yarn.nodemanager.resource.cpu-vcores</name>
    <value>4</value>
  </property>
  <property>
    <name>yarn.scheduler.minimum-allocation-mb</name>
    <value>512</value>
  </property>
  <property>
    <name>yarn.scheduler.maximum-allocation-mb</name>
    <value>3072</value>
  </property>
  <property>
    <name>yarn.nodemanager.vmem-check-enabled</name>
    <value>false</value>
  </property>
  <property>
    <name>yarn.nodemanager.disk-health-checker.max-disk-utilization-per-disk-percentage</name>
    <value>99</value>
  </property>
  <property>
    <name>yarn.log-aggregation-enable</name>
    <value>true</value>
  </property>
</configuration>
EOF

Những điểm cần chú ý:

• yarn.application.classpath + env-whitelist: cho container thấy thư viện Hadoop và HADOOP_MAPRED_HOME.
• vmem-check-enabled=false: tránh YARN kill container vì «virtual memory» (rất hay xảy ra trong Docker/Java 8).
• max-disk-utilization...=99: mặc định 90% — đĩa Docker đầy hơn mức này thì NodeManager bị đánh dấu UNHEALTHY («local-dirs are bad») và không cấp container nào.
• Bộ nhớ 3072 MB ≥ AM (1024) + 2 task (1024 mỗi cái).

11Troubleshooting — tra theo thông báo lỗi

Gõ một phần thông báo lỗi (ví dụ MRAppMaster, return code, Derby) để lọc. Khi chưa rõ lỗi gì, chạy /root/diag.sh trước.

Vì sao Job 1 có thể chết trước khi có Mapper

Lỗi này nằm ở tầng khởi chạy MapReduce/YARN và nạp thư viện, không phải SQL hay dữ liệu ARRAY. Có 7 nguyên nhân thường gặp, hướng dẫn này đã xử lý sẵn:

Thiếu classpath MapReduce

Nếu mapred-site.xml chỉ đặt HADOOP_MAPRED_HOME mà không có mapreduce.application.classpath/yarn.application.classpath thì ApplicationMaster không nạp được MRAppMaster.

Sửa ở bước 4d, 4e

Biến môi trường không tới được tiến trình

source ~/.bashrc bị Ubuntu bỏ qua trong shell không tương tác → start-all.sh, SSH của Hadoop và HiveServer2 có thể thiếu JAVA_HOME, HADOOP_HOME, HADOOP_CONF_DIR.

Sửa ở bước 3a–3d, 8a

Hive 4 mặc định chạy Tez

Không đặt hive.execution.engine=mr thì Hive tìm Tez (chưa cài). Có thêm map-join cục bộ và vectorization gây lỗi ngay khi khởi chạy.

Sửa ở bước 7b

YARN không cấp được container

Bộ nhớ NodeManager, giới hạn bộ nhớ ảo, ngưỡng đĩa 90%, và 10% cho AM → job kẹt hoặc bị kill trước khi có Mapper.

Sửa ở bước 4e, 4f

Metastore Derby phụ thuộc thư mục chạy

URL tương đối databaseName=metastore_db chỉ đúng khi chạy từ /root; hướng dẫn dùng đường dẫn tuyệt đối.

Sửa ở bước 7b

Xung đột Protobuf khi ghi bảng ORC

Hadoop mang protobuf-java-2.5.0 đứng trước Protobuf 3.x của Hive trong classpath của task. Reducer ghi ORC chết với NoSuchMethodError ... Internal.checkNotNull, trong khi truy vấn thường vẫn chạy. Sửa bằng cấu hình, không động đến jar.

Sửa ở bước 7b, 9d

Link tải Hadoop có thể 404

downloads.apache.org chỉ giữ bản mới nhất; hướng dẫn dùng archive.apache.org.

Sửa ở bước 2b

Tra theo thông báo lỗi

NoSuchMethodError / Error: com.google.protobuf.Internal.checkNotNull(Ljava/lang/Object;)Ljava/lang/Object; (reducer chết, return code 2, thường khi INSERT vào bảng STORED AS ORC)

Nguyên nhân
Xung đột Protobuf: classpath của Hadoop có protobuf-java-2.5.0 đứng trước, trong khi bộ ghi ORC của Hive cần Protobuf 3.x. Cả 3 lần thử lại của reducer đều chết giống nhau. Các truy vấn không ghi ORC vẫn chạy bình thường nên lỗi này hiện ra muộn.

Cách xử lý
Đã sửa sẵn ở Phần 7b. Nếu hive-site.xml của bạn chưa có, thêm hai property rồi khởi động lại HiveServer2. Không chép đè hay xóa jar Protobuf. Nếu cần thử nhanh trong một phiên Beeline: SET mapreduce.job.user.classpath.first=true; và ADD JAR /root/apache-hive-4.0.1-bin/lib/protobuf-java-3.24.4.jar;.

Trong container
cp $HIVE_HOME/conf/hive-site.xml $HIVE_HOME/conf/hive-site.xml.bak
sed -i 's#</configuration>#  <property>\n    <name>mapreduce.job.user.classpath.first</name>\n    <value>true</value>\n  </property>\n  <property>\n    <name>hive.aux.jars.path</name>\n    <value>file:///root/apache-hive-4.0.1-bin/lib/protobuf-java-3.24.4.jar</value>\n  </property>\n</configuration>#' $HIVE_HOME/conf/hive-site.xml
xmllint --noout $HIVE_HOME/conf/hive-site.xml && echo "OK hive-site.xml"
grep -c '<property>' $HIVE_HOME/conf/hive-site.xml

Biểu thức HiveQL
str_to_map(concat_ws('~', collect_list(concat(ld.name, '=', d.name))), '~', '=')
